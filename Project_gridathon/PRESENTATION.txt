PROBLEM STATEMENT
-----------------
Predict traffic demand for geohash locations on Day 49 (future) given:
  - Training data: Day 48 (full) + Day 49 (partial early slots) → 77,299 rows
  - Test data: Day 49 (future slots to predict) → 41,778 rows
  - Features: geohash, timestamp (15-min intervals), road attributes, weather,
               temperature, landmarks
  - Target metric: R² on Day 49 predictions


CORE IDEA
---------
Build a spatial graph where geohashes are nodes, connected by proximity
(~1.3 km radius). Apply 1-hop and 2-hop "message passing" (GNN-style) to
aggregate neighbor demand signals.

  > No PyTorch/TensorFlow needed — pure scipy KDTree + numpy

Key intuitions:
  - Demand spillover: busy locations "spread" demand to adjacent ones
  - Sparse geohash rescue: geohashes with no Day-49 data borrow from neighbors
  - Spatial demand surface: neighborhood-level signal at each time slot


DATA OVERVIEW
-------------
  Train shape : (77,299 × 11)
  Test shape  : (41,778 × 10)
  Geohashes   : 1,259 unique
  Lat range   : 5.2377 – 5.4849  (roughly 27 km N-S)
  Lon range   : -90.9723 – -90.5878  (roughly 40 km E-W)
  Time slots  : 96 per day (15-min intervals, 00:00 to 23:45)

STEP 1 — GEOHASH DECODE & SPATIAL GRAPH
-----------------------------------------
  - Decoded all 1,259 geohashes to (lat, lon) using a custom Base-32 decoder
  - Built a KDTree over geohash coordinates
  - Connected geohashes within 0.012° radius (~1.3 km) — average 5.4 neighbors
  - No isolated nodes (every geohash has at least 1 neighbor)

  Graph stats:
    Avg neighbors : 5.4
    Max neighbors : 6
    Isolated nodes: 0


STEP 2 — BASE FEATURE ENGINEERING  (76 features)
--------------------------------------------------
  a) TEMPORAL FEATURES
     - hour, minute, time_idx (0–95 = 96 quarter-hour slots)
     - Cyclical encoding: sin/cos of hour and time_idx

  b) GEOHASH HIERARCHY
     - gh4, gh5, gh6 (prefix truncation for spatial coarsening)

  c) CATEGORICAL IMPUTATION
     - RoadType, Weather: filled with mode from training data
     - Temperature: filled per (geohash, hour) median, then global median

  d) TARGET ENCODING (Bayesian smoothing)
     - Smoothed mean demand per geohash/gh5/gh4/gh6 using Day-48 as prior
     - K-smoothing constant prevents overfitting on rare geohashes

  e) DAY-48 LAG FEATURES
     - lag_d48: exact Day-48 demand at same (geohash, time_idx)
     - Neighbor lags: nb_m4, nb_m2, nb_m1, nb_p1, nb_p2, nb_p4
       (same geohash, ±1 to ±4 slots back/forward)
     - lag_slope, lag_slope_broad: temporal trend of demand in Day-48

  f) DAY-48 AGGREGATE STATS per geohash
     - mean, max, std, median, Q25, Q75
     - hourly means, 6-slot-window means, 2-slot-window means
     - peak time slot + distance from current slot to peak

  g) EARLY DAY-49 FEATURES
     - d49_mean, d49_max, d49_std: early Day-49 stats per geohash
     - d49_last: demand at the last observed Day-49 time slot
     - d49_slope: linear trend of early Day-49 demand
     - early_ratio / early_ratio_smooth:
         How much busier is today (Day 49) vs yesterday (Day 48)?
         Smoothed using gh5-level cluster as a prior (K=5 smoothing)
     - adjusted_lag = lag_d48 × early_ratio_smooth
     - d49_last_ratio: ratio of last D49 slot vs same D48 slot
     - best_ratio = 0.4×d49_last_ratio + 0.6×early_ratio_smooth

  h) WEATHER FEATURES
     - weather_d48: yesterday's weather at same slot
     - weather_changed: binary flag for weather change
     - temp_diff: temperature difference D49 vs D48
     - wx_demand_ratio: how weather change affects demand (from D48 lookup)
     - wx_adj_lag, full_adj_lag: lag × weather correction
     - gh_wx_ratio: per-geohash demand ratio under today's vs yesterday's weather
     - super_lag = lag_d48 × early_ratio_smooth × wx_demand_ratio × gh_wx_ratio
       (the "kitchen sink" rule-based forecast)


STEP 3 — GNN MESSAGE PASSING  (16 features, the core innovation)
-----------------------------------------------------------------
  1-hop aggregation: for each (geohash, time_slot), aggregate over ~1.3 km neighbors

    gnn_lag_mean_1h    — mean neighbor Day-48 demand at same time slot
    gnn_lag_std_1h     — std of neighbor Day-48 demand (spatial heterogeneity)
    gnn_lag_max_1h     — max neighbor Day-48 demand
    gnn_ratio_mean_1h  — mean neighbor early_ratio (neighborhood busyness trend)
    gnn_d49_mean_1h    — mean neighbor Day-49 early demand (sparse geohash rescue)
    gnn_gh_mean48_1h   — mean neighbor Day-48 overall level
    gnn_n_neighbors    — number of spatial neighbors (graph connectivity)
    gnn_full_adj_lag_1h— mean neighbor corrected forecast

  2-hop aggregation: aggregate the 1-hop features one more time (~2.6 km radius)

    gnn_lag_mean_2h    — 2-hop neighbor mean Day-48 demand
    gnn_ratio_mean_2h  — 2-hop neighborhood busyness trend

  Derived GNN features:

    gnn_lag_diff_1h    — own lag minus neighbor lag (anomaly signal)
    gnn_ratio_diff_1h  — own ratio minus neighbor ratio (outlier detection)
    gnn_adj_lag_1h     — own lag × neighbor ratio (GNN-corrected prediction)
    gnn_adj_lag_2h     — own lag × 2-hop neighbor ratio
    gnn_spatial_surf   — gnn_lag_mean_1h × early_ratio_smooth
    gnn_d49_rescued    — own Day-49 mean if available, else neighbor's (rescue)

  TOTAL FEATURES: 92 (76 base + 16 GNN)

================================================================================
  TECHNIQUE INNOVATIONS
================================================================================

  1. MANUAL GNN WITHOUT DEEP LEARNING
     - Built spatial graph using KDTree, no frameworks needed
     - 1-hop and 2-hop message passing in pure numpy
     - Slot-aware aggregation (neighbors at same 15-min slot)

  2. SPARSE GEOHASH RESCUE
     - gnn_d49_rescued: borrows Day-49 signal from neighbors when a
       geohash has no early Day-49 observations

  3. MULTI-LEVEL EARLY RATIO ESTIMATION
     - Individual geohash ratio smoothed with gh5-cluster prior
     - Blended with last-slot ratio + weather correction
     - Result: best_ratio = 0.4×d49_last + 0.6×early_ratio_smooth

  4. WEATHER-ADJUSTED FORECAST
     - Separate weather demand ratio computed from Day-48 lookups
     - super_lag combines all corrections: lag × early_ratio × wx_ratio × gh_wx_ratio

  5. TWO-STAGE PSEUDO-LABELING
     - Pass-1 predictions used as pseudo-labels (weight=0.3)
     - Consistent +0.003–0.004 R² improvement across all models

  6. OOF-CALIBRATED POST-PROCESSING
     - Per-geohash multiplicative bias correction (credibility-weighted)
     - EWM smoothing anchored to actual Day-49 slot-8 demand
     - All validated on Day-49 OOF before test application
